# Write a task an engineer can finish

- Start with the reader’s goal. Give the short answer first, then the smallest complete example, then the details a reader needs when adapting it. Roughly five, fifty, and five hundred words is a guide to depth.
- Take one example from prerequisites to a result the reader can find. Check that referenced images, executables, configs, and models are available to public users. Name any required access. A public source repository alone does not establish that an image exists.
- Use a table for choices, a list for steps, and a small diagram for a handoff. Label each component with the name a reader sees in code or the CLI. Label an arrow with the command, request, or data that crosses it.
- Keep the README useful on GitHub. Show the first useful action inline. Link deeper instructions once and check the destination in the rendered navigation. Check diagrams on light and dark backgrounds.
- Read just the headings and the example. Can a new user tell what to supply, what runs, and where to look for the result?
